# Content schema: the contract between the OS and this site

The PPM AI OS publishes to this site by committing **one JSON file** to `main`:
`content/blog/<slug>.json` for a post, `content/areas/<slug>.json` for a town or county page. Vercel
builds. Everything else a page needs (its listing on `/blog/`, its pillar hub and `/service-areas/`,
internal links, related posts, JSON-LD, sitemap `<lastmod>`, `llms.txt` entry) is generated by the
site from that one file. The OS never writes `src/`, `public/`, `content/redirects/` or
`content/blog-extras/`.

Where it is enforced:

- `src/content.config.ts`: the zod schema (shape and types). A file that fails it fails the build.
- `src/lib/site-guard.mjs`: the rules zod cannot express, run on every file by
  `scripts/check-content.mjs` before every build (`prebuild`) and mirrored by the OS's
  `supabase/functions/_shared/siteGuard.ts` before it commits.

Every field marked optional may be left out; a file written before these fields existed still
validates and renders. Unknown fields are ignored (not rendered, not an error).

Dates are `"YYYY-MM-DD"`, must be real calendar dates, and must not be after today in New Jersey
(America/New_York) at build time. `dateModified` must be on or after `datePublished`.

## Blog post: `content/blog/<slug>.json`

URL: `/<path>/`.

| Field | Required | Type | Rendered as |
|---|---|---|---|
| `path` | yes | `"blog/<pillar>/<slug>"`, no slashes at the ends | the URL. Must start with `blog/` and must not be claimed by another page. |
| `title` | yes | string | h1, breadcrumb, listings, BlogPosting `headline` |
| `titleTag` | no | string | `<title>` (default: `title`) |
| `description` | yes | string, max 165 chars | meta description, listings |
| `pillar` | yes | `{ "name": string, "path": "blog/<hub>" }` | badge, breadcrumb, related posts, hub listing. The hub page must exist. |
| `author` | yes | string | byline, BlogPosting `author` |
| `authorType` | yes | `"Organization"` or `"Person"` | BlogPosting `author.@type` |
| `datePublished` | yes | date | byline, BlogPosting, `article:published_time` |
| `body` | yes | HTML | the article. Internal links need a trailing slash and must point at a page that exists. No draft or reviewer notes. No JSON-LD that repeats the template's types. |
| `dateModified` | no | date, `>= datePublished` | "updated <date>" in the byline; BlogPosting `dateModified` and `article:modified_time` (both fall back to `datePublished`); listing order and sitemap `<lastmod>` use `dateModified || datePublished` |
| `primaryKeyword` | no | string | not rendered; kept for the OS's SEO tracking |
| `audience` | no | `"owner"` (default) or `"tenant"` | owner: mid-article CTA, CTA band, "Next step" links to `/get-started/`, `/landlord-checklist/`, `/pricing/`. tenant: no mid-article CTA (a `<!--MID_CTA-->` marker is dropped), no CTA band, "Next step" links to `/rentals/` and `/tenants/` |
| `faq` | no | `[{ "question": string, "answer": string }]`, non-empty | FAQPage JSON-LD; plus a visible "Frequently asked questions" list of every question whose text the body does not already contain. Must not also be in the post's blog-extras file. |
| `sources` | no | `[{ "title": string, "url": "https://..." }]`, non-empty | a "Sources" list at the end of the article, links `rel="noopener"` in a new tab. https only. |
| `legalDisclaimer` | no | boolean | the "general information, not legal advice" line under the article. Default: on when `pillar.path` is `blog/nj-landlord-law` and the body does not already say "not legal advice"; otherwise off. Precedence: post JSON, then blog-extras, then the default. |

Always generated for a post: a table of contents when the body has 4 or more `<h2>` (an h2 without
an `id` gets one, derived from its text, made unique); up to 3 related posts (same pillar, newest by
`dateModified || datePublished`, excluding itself) in the aside; `og:type=article` with
`article:section` = pillar name; the post in the "Latest articles" list on `/blog/` (12 newest),
under its topic on `/blog/`, on its pillar hub (all posts, newest first), in `llms.txt`, and in the
sitemap with `<lastmod>`.

`content/blog-extras/<slug>.json` (site-maintained, optional) still works: `socialTitle`, `faq`
(JSON-LD only; its questions are already in the body) and `legalDisclaimer`.

Example:

```json
{
  "path": "blog/nj-landlord-law/smoke-detector-rules-nj",
  "title": "NJ Smoke and CO Alarm Rules for Landlords",
  "description": "What New Jersey requires of landlords for smoke and carbon monoxide alarms, and when a certificate is needed.",
  "pillar": { "name": "NJ Landlord Law", "path": "blog/nj-landlord-law" },
  "author": "Proactive Property Management",
  "authorType": "Organization",
  "datePublished": "2026-11-02",
  "dateModified": "2026-11-09",
  "primaryKeyword": "nj smoke detector requirements landlord",
  "audience": "owner",
  "faq": [{ "question": "Who issues the certificate?", "answer": "The local fire official." }],
  "sources": [{ "title": "NJ DCA, Division of Fire Safety", "url": "https://www.nj.gov/dca/divisions/dfs/" }],
  "body": "<h2 id=\"overview\">Overview</h2><p>...</p>"
}
```

## Area page: `content/areas/<slug>.json`

URL: `/service-areas/<slug>/`, for towns and counties alike. The slug (file name) is lowercase words
joined by hyphens and must not collide with another route. The following slugs are currently
redirected to `/service-areas/` by legacy redirects and are refused until a person removes the row
from `content/redirects/*.csv` (and regenerates `vercel.json`): belleville, bloomfield, elizabeth,
fairlawn, fort-lee, franklin-township, garfield, irvington, kearny, livingston, middletown-township,
montclair, new-brunswick, north-bergen, old-bridge-township, passaic, piscataway, teaneck,
union-city, union-township, wayne, west-new-york, west-orange, woodbridge-township.

| Field | Required | Type | Rendered as |
|---|---|---|---|
| `kind` | no | `"town"` (default) or `"county"` | a county page lists its towns, its rent-control line says rent control is set town by town, and its ProfessionalService `areaServed` is an `AdministrativeArea` in New Jersey (a town's is a `City`) |
| `name` | yes | string | page name, breadcrumb, listing on `/service-areas/` |
| `county` | yes | string, e.g. `"Hudson County"` | hero label and the group on `/service-areas/`. A county page names itself. |
| `rentControl` | yes | boolean | town hero: "has a municipal rent control ordinance" + lookup link; listing note ", rent control". Ignored on a county page. |
| `seo` | yes | `{ "title", "description", "social"?: { "title"?, "description"? }, "twitter"?: { "site"?: boolean, "title"?, "description"? } }` | `<title>`, meta description, Open Graph, Twitter |
| `h1` | yes | string | h1 |
| `intro` | yes | string | hero lead |
| `hero` | no | `{ "image", "webpWidth", "width", "height", "alt", "creditHtml"? }` | hero photo from `public/images/service-areas/<image>-hero.{jpg,webp}` and `-hero-768.webp` (the OS cannot add images, so new pages leave it out) |
| `breadcrumbHubLabel` | yes | string (`"Areas"`) | breadcrumb label for `/service-areas/` |
| `contentHtml` | yes | HTML | main column. Internal links need a trailing slash and must exist. |
| `sidebar` | yes | `{ "ctaText", "nearbyLabel", "nearby": [{ "href", "label" }], "guides": [{ "href", "label" }] }` | aside link lists (`ctaText` is kept but not rendered). Links must exist. |
| `cta` | yes | `{ "heading", "text" }` | closing CTA band |
| `towns` | no, county only | `[area slug]` | "Towns we serve in <name>", linked. Each must have a `content/areas/<slug>.json`. A town listed here (or whose `county` equals the county page's `name`) gets the county in its breadcrumb. |
| `faq` | no | `[{ "question", "answer" }]`, non-empty | a visible "Frequently asked questions" list and FAQPage JSON-LD. Do not repeat the questions in `contentHtml`. |
| `localFacts` | no | `[{ "label", "text", "sourceTitle", "sourceUrl": "https://..." }]`, non-empty | "Local rules at a glance": each fact with a linked source |
| `datePublished` | no | date | "Published <date>" at the end of the main column; sitemap `<lastmod>` |
| `dateModified` | no | date, `>= datePublished` (needs `datePublished`) | "Updated <date>" instead; sitemap `<lastmod>` |

Always generated for an area: its row on `/service-areas/` under its county (a county page first in
its group), its `llms.txt` entry, its sitemap entry (with `<lastmod>` when it has a date), and a
hand-written "other towns we serve" row for the same town name is dropped from `/service-areas/`.

## Refused by the content check

- A date that is not a real `YYYY-MM-DD`, is in the future, or a `dateModified` before
  `datePublished` (posts and areas).
- A malformed `faq`, `sources` or `localFacts` entry (missing or empty fields, empty list), or a
  source / fact URL that is not `https://`.
- `faq` in both a post's JSON and its `content/blog-extras` file.
- `audience` other than owner/tenant; `kind` other than town/county; `towns` on a town page.
- A county `towns` entry with no `content/areas/<slug>.json`, or listing itself.
- An area slug that is not lowercase-hyphenated, is claimed by another source route, or is a
  redirect source.
- Everything refused before: missing required fields, a description over 165 characters, a pillar
  with no hub, internal links without a trailing slash or to missing pages, draft or reviewer notes,
  body JSON-LD that repeats template types or names another domain.

External links inside a post `body` are not refused (published posts cite inline); new citations
belong in `sources`.
